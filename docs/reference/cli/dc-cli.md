# dc-cli reference

`dc-cli` is DrorControl's command-line tool: the same Rust core as the app, for scripting,
bench tests and post-flight analysis. Generated by `scripts/gen_cli_docs.py` from the tool's
own `--help`; run it again after changing a command.

Commands that read logs work on a file and never touch a vehicle. Commands that talk to a
vehicle (`params`, `mission download`, `log list`/`download`, `telemetry`, `cot`, `daemon`)
open the link given with `--connect` (for example `tcp:127.0.0.1:5760`, `udp:0.0.0.0:14550`,
`serial:/dev/tty.usbmodem1:115200`).

## Common tasks

| Task | Command |
|---|---|
| Everything about a flight log | `dc-cli log report FLIGHT.BIN` |
| Health checks for CI (non-zero exit on a warning) | `dc-cli log health FLIGHT.BIN --json --fail-on warning` |
| Health from telemetry only | `dc-cli tlog health FLIGHT.tlog` |
| Share a log without revealing where it was flown | `dc-cli log sanitize FLIGHT.BIN --out SHARE.BIN` (`tlog sanitize` for recordings) |
| Make a log smaller (the armed time only) | `dc-cli log trim FLIGHT.BIN --out SHORT.BIN` |
| Track for Google Earth, by flight mode | `dc-cli log export FLIGHT.BIN --kml FLIGHT.kml` |
| Parameters that switch off safety nets | `dc-cli params-review FLIGHT.BIN` |

Never commit field logs with real positions to the repository; sanitize them first
(ADR-0012).

## `dc-cli`

```text
DrorControl command-line tool

Usage: dc-cli [OPTIONS] <COMMAND>

Commands:
  params          Download all parameters and print them (or write a .param file)
  param-get       Read named parameters without downloading the whole list (fast over a radio)
  param-set       Change parameters on the vehicle (ADR-0012): every change is listed and confirmed once; if the vehicle is armed, its in-flight warning must be acknowledged too. A baseline of all parameters is saved first, each value is read back, and every step is audited
  param-rollback  Restore parameters from a baseline saved by `param-set` (the vehicle in the baseline): the named ones, or with --changed every one that now differs (except values the autopilot maintains itself). Same confirmation, in-flight warning, new recovery baseline, read-back and audit as `param-set`
  daemon          Run the core with the gRPC API (proto/dc/v1/core.proto) until interrupted
  about           This build and machine, for test reports: version, OS and architecture, serial ports seen, and the firmware versions tested in CI
  audit-verify    Check an audit log's hash chain (commands and parameter writes): every record links to the one before, so an edited, removed or reordered line is found. Prints the records with --print
  remote          Talk to a running daemon over gRPC
  ports           List serial ports with board hints; optionally watch hotplug or probe for MAVLink
  soak            Serial integrity soak: stream MAVLink frames out of `tx` and verify them on `rx` (same port with a TX-RX loopback jumper, or two adapters cross-wired)
  params-review   Which safety nets a parameter set has switched off (advisory; .param or .bin)
  params-diff     Compare two parameter sets, each a .param file or the parameters recorded in a .bin log
  log             Dataflash (.bin) log tools: index statistics and downsampled plots, with timings
  mission         Mission files (QGC WPL 110, Mission Planner's .waypoints): download, check, compare. Read-only: uploads stay behind the core's interlocks and are not offered here yet
  tlog            Telemetry logs (.tlog, as recorded with --tlog or by Mission Planner)
  cot             Cursor-on-Target position events for every vehicle (ATAK/WinTAK/TAK), printed or sent over UDP (e.g. the ATAK multicast 239.2.3.1:6969)
  telemetry       Print a telemetry summary once per second
  help            Print this message or the help of the given subcommand(s)

Options:
      --sysid <SYSID>    Our MAVLink system id (the vehicle's SYSID_MYGCS should match) [default: 255]
      --compid <COMPID>  Our MAVLink component id [default: 190]
      --tlog <TLOG>      Record everything to this .tlog file
  -h, --help             Print help
  -V, --version          Print version
```

### `dc-cli params`

```text
Download all parameters and print them (or write a .param file)

Usage: dc-cli params [OPTIONS] --connect <CONNECT>

Options:
      --connect <CONNECT>      Link, e.g. tcp:127.0.0.1:5760, udp:0.0.0.0:14550, serial:/dev/ttyACM0:115200, tlog:flight.tlog@4 (replay)
      --sysid <SYSID>          Our MAVLink system id (the vehicle's SYSID_MYGCS should match) [default: 255]
      --compid <COMPID>        Our MAVLink component id [default: 190]
      --target <TARGET>        Target system id (default: first vehicle heard)
      --component <COMPONENT>  Target component id [default: 1]
      --tlog <TLOG>            Record everything to this .tlog file
      --out <OUT>              Write a Mission Planner-compatible .param file instead of printing
      --compare <COMPARE>      Compare the vehicle with this .param file or .bin log instead of printing; exits with failure on any difference (read-only)
      --wait <WAIT>            Seconds to wait for a vehicle heartbeat [default: 15]
  -h, --help                   Print help
```

```text
Change parameters on the vehicle (ADR-0012): every change is listed and confirmed once; if the vehicle is armed, its in-flight warning must be acknowledged too. A baseline of all parameters is saved first, each value is read back, and every step is audited

Usage: dc-cli param-set [OPTIONS] --connect <CONNECT> [NAME=VALUE]...

  [NAME=VALUE]...  Changes as NAME=VALUE
```

### `dc-cli daemon`

```text
Run the core with the gRPC API (proto/dc/v1/core.proto) until interrupted

Usage: dc-cli daemon [OPTIONS]

Options:
      --connect <CONNECT>        Links to open at start (repeatable)
      --sysid <SYSID>            Our MAVLink system id (the vehicle's SYSID_MYGCS should match) [default: 255]
      --compid <COMPID>          Our MAVLink component id [default: 190]
      --listen <LISTEN>          gRPC listen address, e.g. 0.0.0.0:50051 for a field network. Beyond loopback an API key is required (--token-file or DC_API_TOKEN) [default: 127.0.0.1:50051]

      --audit <AUDIT>            Hash-chained audit log (commands and parameter writes) [default: dc-audit.log]
  -h, --help                     Print help
```

### `dc-cli log`

```text
Dataflash (.bin) log tools: index statistics and downsampled plots, with timings

Usage: dc-cli log [OPTIONS] <COMMAND>

Commands:
  info         Index a log and print message counts, timings and memory use
  list         List the dataflash logs on the vehicle (over MAVLink; vehicle must be disarmed)
  download     Download a dataflash log from the vehicle over MAVLink (vehicle must be disarmed). Written to OUT.partial and renamed when complete. Logs are never erased
  compare      Two flights side by side: time, altitude, distance, speeds, battery, motors, tracking
  report       Every analysis at once: summary, health, motors, attitude, battery, compass, wind, sensors, RC link, notch advice and parameter changes
  summary      Flight summary: armed time, highest altitude, top speed, distance, battery used
  events       Timeline of mode changes, arming, events, errors and messages
  changes      Parameters changed after boot (values the autopilot updates itself are marked)
  motors       Motor outputs while flying: how hard each motor works compared with the others
  geotags      Photos in the log (CAM records) as CSV for geotagging, with UTC from the GPS time
  notch        Throttle-based harmonic notch settings suggested from the flight (advice only; nothing is written to the vehicle)
  rc           RC link: receiver RSSI and link quality while armed, radio failsafes, late frames
  sensors      Optical flow and rangefinders while flying: could the EKF use them?
  altitude     Do the altitude sources agree while flying (barometer vs EKF, GPS vs EKF)?
  gps          GPS quality while armed: satellites, HDOP, fix types, glitches
  wind         Wind while flying, as the EKF estimated it
  imu          IMU health: temperatures, error counts, unhealthy samples while armed, sample rates
  sanitize     Write a copy with every position moved to a stand-in location (shapes and distances kept), so the log can be shared without revealing where it was flown
  trim         Write a smaller copy holding only a time window (default: the armed time with a margin), with the formats, parameters and boot messages that explain it
  failsafes    Every failsafe in order: what triggered, what the vehicle did, when it cleared
  takeoffs     Takeoffs: time from arming to liftoff, climb, attitude error just after liftoff
  landings     Landings: descent speed before touchdown, time to disarm
  lanes        EKF lane switches (primary core changes), flagged when armed
  cells        Battery cell balance while flying (packs that report cell voltages)
  perf         Autopilot performance: loop rate and overruns, processor load, memory, internal errors
  esc          ESC telemetry while armed: RPM, error rate, temperature and current per ESC
  compass      Compass interference: field strength against battery current while flying
  battery      The battery under load while flying: current, power, voltage sag, use, resistance
  attitude     Attitude tracking while flying: desired minus achieved roll, pitch and yaw
  fft          Vibration spectrum (Welch FFT) of an IMU axis while armed, and its strongest peaks
  spectrogram  How the vibration spectrum changes over the flight and with throttle: the strongest frequency per throttle band (motor-harmonic lines move with throttle), and optionally the full spectrogram as CSV (one row per second)
  csv          Every record of one message as CSV (all fields; text quoted)
  params       The parameters recorded in the log as a .param file
  health       Automatic checks: vibration and clipping, battery against the vehicle's failsafe voltages, EKF variances against FS_EKF_THRESH, and the autopilot's ERR records
  export       Export the flight track (EKF position, UTC from the GPS clock) as GPX and/or KML
  plot         Extract MSG.FIELD and downsample it (MinMaxLTTB) for plotting
  help         Print this message or the help of the given subcommand(s)

Options:
      --sysid <SYSID>    Our MAVLink system id (the vehicle's SYSID_MYGCS should match) [default: 255]
      --compid <COMPID>  Our MAVLink component id [default: 190]
      --tlog <TLOG>      Record everything to this .tlog file
  -h, --help             Print help
```
